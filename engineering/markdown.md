# Markdown 与 Obsidian 笔记规范

> 用途：统一个人知识库的 Markdown 写法、目录组织和 Obsidian 内链方式。
> 适用类型：知识 / 教程 / 项目 / 索引

## 核心原则

- Markdown 标题、列表、代码块和表格参考通用 Markdown 与 [Google Markdown 风格](https://developers.google.com/style/markdown)。
- 笔记之间的关联使用 Obsidian 官方内链语法，例如 `[[sql]]` 或 `[[sql#窗口函数|窗口函数]]`。
- 目录和文件按主题组织；文件名简洁、明确，不为了形式强行使用编号。
- 一个文件服务一个主要主题，但相关内容足够少时不强行拆分。
- 通用内容只维护一份，相关笔记通过内链复用，不复制相同解释。
- 先保证可读、可查和可维护，再考虑格式统一。

## 标题层级

- 每个文件只保留一个一级标题 `#`，作为文件主题。
- 主要分区使用 `##`，具体主题使用 `###`，必要时再使用 `####`。
- 标题层级连续递进，不从 `#` 直接跳到 `###`。
- 代码块中的 `#` 注释不是 Markdown 标题，不参与层级判断。
- 标题只写主题，不添加章节号或题号，例如 `## 基础查询`。
- 日期、版本和术语中的数字保留，例如“第一范式（1NF）”。

```md
# SQL 基础与查询

## 多表连接

### LEFT JOIN

#### `ON` 与 `WHERE` 的区别
```

## 文件开头

正文开头先说明这份笔记解决什么问题。教程和项目记录可以使用属性区：

```md
---
date updated: 2026-10-25
---

# 主题名称

> 用途：一句话说明这份笔记的目的。
> 适用类型：知识 / 教程 / 项目 / 索引
```

没有必要的属性或简介时，不为了套模板而添加。

## 内容组织

### 知识笔记

先写结论，再补原理、示例和边界：

- 结论：先回答是什么、何时使用。
- 原理：只保留理解和使用必需的内容。
- 示例：给出可以运行或明确标注方言的例子。
- 边界：说明常见误区、限制和不能直接套用的情况。

### 教程与操作记录

按执行顺序组织：

1. 前置条件。
2. 操作步骤。
3. 验证结果。
4. 常见问题和排错方式。

命令、路径、版本、参数和风险提示不能省略；背景解释可以压缩。

### 项目记录

至少区分背景、目标、个人职责、关键做法、结果和待确认事项。团队成果不要直接写成个人成果，未确认的信息标记为“待确认”。

### 索引页

只保留用途、目录、入口和阅读顺序。使用内链指向实际笔记，不重复介绍被链接文件的正文。

## Markdown 写法

### 段落与列表

- 段落尽量控制在 2～4 句。
- 并列知识点、原则、检查项和注意事项使用无序列表 `-`。
- 步骤、优先级和学习顺序使用 `1. `、`2. `、`3. `；不为并列内容添加编号。
- 此规范同时适用于 `.md` 和 `.ipynb` 的 Markdown 单元；代码和输出不参与排版替换。
- 列表项只表达一个动作或事实，避免多层嵌套。
- 中英文、数字和单位之间保留清晰空格，术语和标点保持一致。

### 代码与命令

- 命令、路径、文件名、类名、字段名和参数使用反引号。
- 可执行命令使用带语言标记的代码块，例如 ` ```bash `。
- 代码块应能复制运行；不能运行时注明环境、版本或伪代码性质。
- 解释代码时优先说明输入、输出和关键限制，不逐行复述显而易见的语句。

```bash
uv run pytest
```

### 表格

表格适合字段、对比、规则和清单。内容过长或需要完整解释时，改用小标题和列表。

### 链接

- 同一目录内有关联的笔记优先使用 Obsidian 内链：`[[fastapi]]`。
- 需要跳转到具体位置时使用标题锚点：`[[sql#窗口函数、子查询与 CTE：如何选择]]`。
- 需要显示更短或更清晰的文字时使用别名：`[[fastapi|FastAPI 教程]]`。
- 完全独立的目录或主题不要为了完整而强行互链。
- 外部资料使用普通 Markdown 链接：`[Google Markdown style guide](https://developers.google.com/style/markdown)`。

Obsidian 的内链、嵌入、属性和其他语法以[官方帮助文档](https://help.obsidian.md/)为准。

## 命名与目录

- 文件名使用短而明确的主题名，例如 `sql.md`、`fastapi.md`、`testing.md`。
- 同一目录中的文件按主题归类，不把所有内容拆成过多小文件。
- 只有存在明确阅读或执行顺序时才使用数字前缀，并在 README 中说明顺序。
- README 作为目录索引，可以使用 Obsidian 内链指向子目录中的笔记。
- 改名或移动文件后同步更新内链、README 和相关引用。

## 精简与维护

可以删除：

- 重复结论。
- 过时内容。
- 没有实际入口或行动价值的目录项。
- 与文件主题无关的背景。

不能直接删除：

- 教程的前置条件、验证步骤和错误处理。
- 会影响结果的参数、版本差异和限制。
- 项目记录中的个人贡献、结果和待确认事项。

每次修改后检查：

- 标题是否只有一个一级标题且没有跳级。
- 代码块、表格、命令和路径是否可用。
- 内链目标是否存在，标题锚点是否仍然有效。
- README 是否仍能作为当前目录的入口。
- 通用内容是否被重复复制到其他笔记。
